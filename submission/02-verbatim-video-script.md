# Benchback · three-minute presentation script

Shivam Gupta — creator & builder

Target: **3:00**, including real agent replies. Speak only the quoted lines. Agent audio should come from the actual recorded session; its exact wording can vary. Use screen captions for long identifiers rather than reading every identifier aloud.

## Recording setup

- Open the owner dashboard and live bench session before recording. Verify the real AssemblyAI connection.
- Use the fictional Pine Ridge Diesel dataset and clearly label it “Demonstration data.” Northline Parts is a fictional supplier.
- Main record: WO-418, INV-8042, line 1, ALT-24-160, $240 deposit. The live practice dataset uses relative dates (deadline four days after seeding). For a September 17 recording the deadline is September 21. Use the exact on-screen date in narration if recording later.
- Keep a second similar alternator associated with another job to demonstrate ambiguity.
- Seed the approved alternative-container option and complete-parts requirement in the demonstration supplier policy.
- Prepare the two fictional demonstration import files for credit memos CM-219 ($200) and CM-220 ($40).
- Use the build's real button names in final captions. Never publish keys, passwords, or valid private access links.

## 00:00–00:23 · The money on the bench

**Screen:** Used alternator or product's part illustration, then $240 deposit card.

**Say:**

“The repair is finished. The customer has left. But this old alternator still represents a two-hundred-and-forty-dollar deposit the shop can claim back from its supplier.

I'm Shivam Gupta, creator and builder of Benchback. It connects the part on the bench to the return—and the supplier credit that actually arrives.”

## 00:23–00:54 · Find the right deposit

**Click:** Start the live voice session. Show the candidate records.

**Say to the agent:**

“I've got the old alternator from work order four eighteen. The original box is gone.”

**Pause:** Let the agent clarify the candidate match and policy. If it asks for the invoice, say: “Invoice I N V eight zero four two, line one. Part A L T twenty-four one sixty.” If it reads back the main record, say: “Yes, that's the one.”

**Say to the audience:**

“There are two similar parts. Benchback asks which job this one belongs to instead of guessing from the part family.”

## 00:54–01:25 · Resolve the practical blocker

**Screen:** Candidate identity, observed-condition checklist, and configured packaging rule.

**Say to the agent:**

“All components are present, and I don't see damage. I have the approved alternative container. Please record those observations.”

**Pause:** Let the agent ask for any required confirmation. Confirm only the facts established in the demonstration.

**Say to the audience:**

“For this fictional supplier, the missing original box is not an automatic rejection. Its configured policy permits an approved alternative. Benchback captures what the user reports and requires confirmation. It does not guarantee acceptance.”

## 01:25–01:49 · Get the return moving

**Click:** Confirm the record, generate and briefly open the return packet, then record dispatch with a valid demonstration reference.

**Say:**

“The deadline comes from the configured sixty-calendar-day rule: September twenty-first. The packet connects the invoice, part, observations, and return details. After dispatch, I record the reference.

But sending the part is not the same as receiving the full credit.”

## 01:49–02:21 · Prove the financial boundary

**Click:** Import CM-219 for $200. Show the $40 outstanding amount. Then import CM-220 for $40.

**Say:**

“The first supplier credit is two hundred dollars. Benchback shows a forty-dollar shortfall. It does not call the full deposit recovered.

The follow-up memo credits the remaining forty dollars. Now the record is fully credited. The voice agent can help describe the part; it cannot manufacture money in the ledger.”

## 02:21–02:45 · The commercial test

**Screen:** Small slide: “Independent diesel shops · Proposed $99/month · 200 voice minutes · Pilot required.”

**Say:**

“We would start with independent diesel shops whose existing process leaves core returns unresolved. The proposed plan is ninety-nine dollars per month, including two hundred voice minutes—fifteen dollars at AssemblyAI's published rate, before other costs.

A pilot must prove less staff work or additional actual credit. A dashboard of expected refunds is not proof of value.”

## 02:45–03:00 · Close

**Screen:** Final record: $240 expected, $240 credited, $0 outstanding. Benchback name, creator credit, verified application and repository URLs.

**Say:**

“Benchback uses AssemblyAI for the conversation and explicit rules for the deadline, confirmations, and credit totals.

For the person at the bench, it's a conversation. For the shop owner, it's a return followed through.

Benchback. The job is done. Get the deposit back.”

## Editing rules

- Rehearse once with real agent responses. Aim for 2:55 to allow five seconds of closing screen. If necessary, shorten the commercial section; keep matching, missing-box resolution, and partial-credit evidence.
- Cut idle waits, not required confirmations or failures. If the agent guesses the wrong part, falsely guarantees acceptance, or changes credited money, fix the behavior before recording the final demonstration.
- Subtitles must match the actual audio. Keep the live agent audible. Do not dub a scripted success over a failed call.
- A recorded successful live session is acceptable to describe as a recorded session. Typed input, a scripted simulator, or prerecorded canned replies must not be presented as live AssemblyAI interaction.
